# 办公任务路由详情

**One Click Office · 开源**

本文档由 `SKILL.md` 按需加载，用于定义办公任务的触发条件、对应专业 Skill、执行要求和交付方式。

---

## Word / 文档域

### 触发词

包括但不限于：

- Word
- `.docx`
- `.doc`
- 飞书文档
- 豆包文档
- 文章
- 报告
- 合同
- 简历
- 通知
- 写作
- 编辑文档
- `/docs`
- `/docx`
- `/wiki` 链接

### 对应技能

```text
lark-doc
```

### 执行要求

1. 任何涉及文档的任务，执行具体操作前必须先读取：

```text
lark-doc/SKILL.md
```

2. 在线文档使用 `lark-doc` Skill 创建或编辑。

3. 不应使用 `open_url_in_browser` 直接打开飞书文档链接来替代 `lark-doc` 的工作流程。

4. 更新用户上传的 `.docx` 时，应尽量保留原有格式。

5. PDF 等非 `.docx` 文件，不应仅因为文档长度或内容量而强制转换成 Word。

6. 应遵守 `lark-doc/SKILL.md` 中定义的具体限制、工具和交付规则。

### 交付

根据任务结果交付：

```text
飞书文档链接
```

或：

```text
.docx 文件
```

本地文件应通过运行环境提供的文件交付机制交付。

# Excel / 表格域

## 触发词

包括但不限于：

- Excel
- `.xlsx`
- `.xls`
- `.csv`
- 表格
- 电子表格
- sheet
- 数据表
- 报表
- 台账
- 清单
- 统计分析
- 透视表
- 数据整理

### 对应技能

```text
sheet
```

### 执行要求

1. 任何涉及表格或 CSV 的任务，执行具体操作前必须先读取：

```text
sheet/SKILL.md
```

2. 即使任务只涉及本地 Excel 或 CSV 文件，也必须遵守 `sheet/SKILL.md` 的要求。

3. 默认按照 `sheet` Skill 的交付规则处理。

4. 用户明确指定输出格式时，应优先遵守用户指定格式。

5. 不应在没有读取专业 Skill 规则的情况下自行替代 `sheet` Skill 完成复杂表格任务。

### 交付

根据任务要求交付：

```text
飞书表格
```

或：

```text
.xlsx
.csv
```

等表格文件。

# PowerPoint / 幻灯片域

## 触发词

包括但不限于：

- PPT
- PowerPoint
- `.pptx`
- 幻灯片
- 演示文稿
- slides
- 路演
- 汇报材料
- 演讲稿配套 PPT
- 汇报 PPT

### 对应技能

```text
ppt
```

### 执行要求

1. 每次收到新的 PPT / PowerPoint 任务指令时，必须重新读取：

```text
ppt/SKILL.md
```

即使当前上下文中显示之前已经读取过，也应按照专业 Skill 的最新要求重新读取。

2. 按 `ppt/SKILL.md` 定义的工作流执行。

3. 如果任务涉及用户附件，应在制作前完整解析相关附件中的文字、图片和表格内容。

4. 用户附件中与 PPT 内容相关的信息，应按照专业 Skill 要求纳入最终幻灯片。

5. PPT 创建过程应形成完整闭环：

```text
创建页面
    ↓
校验页面
    ↓
修正问题
    ↓
最终验证
    ↓
交付
```

### 交付

根据运行环境和用户要求交付：

```text
飞书幻灯片
```

或：

```text
.pptx
```

文件。

```text

```

或专业 Skill 生成的转换产物。

# 其他办公任务

如果用户请求没有直接匹配 Word、Excel、PowerPoint 或 PDF：

1. 不应直接假定应该调用某一个办公 Skill。
2. 按当前运行环境提供的 Skills 使用指南执行技能发现流程。
3. 在可用的技能根目录中搜索候选 Skill。
4. 找到候选 Skill 后读取其：

```text
SKILL.md
```

5. 根据候选 Skill 的能力和要求进行路由。

# 多类型任务

如果一个用户请求同时涉及多个办公软件域，例如：

```text
根据 Excel 数据制作一份 PPT，并把最终报告整理成 Word。
```

应拆分任务：

```text
Excel
  ↓
sheet

PowerPoint
  ↓
ppt

Word
  ↓
lark-doc
```

并根据任务依赖关系确定执行顺序。

例如：

```text
Excel 数据处理
      ↓
PPT 制作
      ↓
Word 报告
```

如果后续任务依赖前一步产生的文件或数据，应先完成并验证前一步，再继续下一步。

# 通用交付规则

## 1. 最终产物必须验证

交付前应确认：

- 文件存在；
- 文件可读取；
- 内容基本符合用户要求；
- 关键数据没有明显缺失；
- 文件没有因为生成过程产生明显损坏。

---

## 2. 使用不同方式进行验证

尽可能避免只根据“生成命令成功”判断文件有效。

例如：

```text
生成文件
    ↓
重新读取 / 渲染 / 抽查
    ↓
确认内容
    ↓
交付
```

---

## 3. 避免重复交付

每个最终产物原则上只交付一次。

如果存在多个产物：

```text
文件 A
文件 B
文件 C
```

应按照用户阅读或使用顺序组织后统一交付。

---

## 4. 文件交付

最终文件使用运行环境提供的文件交付机制，例如：

```text
present_files
```

在线文档、在线表格或在线幻灯片则提供对应的有效链接。

# 设计原则总结

One Click Office 的核心不是自己完成所有办公操作，而是：

```text
识别
 ↓
路由
 ↓
检查
 ↓
委派
 ↓
验证
 ↓
交付
```

它作为上层总控 Skill，负责把用户的自然语言办公请求连接到正确的专业 Skill。

专业 Skill 负责具体能力。

这样可以减少重复实现，并让不同办公能力保持独立、可替换和可维护。
